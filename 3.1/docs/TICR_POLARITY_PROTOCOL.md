# TICR：五个道德基础维度的极性二分类

## 1. 任务与答案

| 任务 | 正向标签及答案 | 负向标签及答案 | 测试图文判断对 |
|---|---|---|---:|
| care | Care → 关怀 | Harm → 伤害 | 72 |
| fairness | Fairness → 公平 | Cheating → 欺骗 | 42 |
| loyalty | Loyalty → 忠诚 | Betrayal → 背叛 | 63 |
| authority | Respect → 权威 | Subversion → 颠覆 | 55 |
| sanctity | Sanctity → 纯洁 | Degradation → 污秽 | 56 |

每个维度只纳入至少一极被标注的场景；未标注不等于负向，不生成该任务样本。同维度双极同时标注直接拒绝。一个场景可参与多个维度，但原训练、验证、测试划分不变。五个任务共用同一生成模型与语言 LoRA；图像和文本独立输入，不是十个独立二分类器。

问题示例：“根据本数据集的标注，以下图片中的场景属于关怀/伤害道德基础维度。请判断该场景体现的是关怀还是伤害。只回答‘关怀’或‘伤害’，不要标点或解释。”输入已给定任务所属维度，因此本指标是条件极性判断，不同时测量维度发现能力。

图片路只有图片和问题；文本路只有固定 caption 0 与对应问题，不含图像 token。推理代码不读取参考 assistant 回答。答案只允许对应任务的两个中文标签，忽略首尾空白；标点、解释、是/否、其他任务标签均无效。原始回答始终保留。

## 3. TICR 与正确性

令第 k 个维度的有效标注场景集合为 S_k，两种模态各生成一个最终答案。两路答案均合法且相同记为一致，否则为不一致。

\[
\mathrm{TICR}=\frac{1}{5}\sum_{k=1}^{5}\frac{1}{|S_k|}
\sum_{i\in S_k}\mathbf{1}[\hat y^I_{ik}=\hat y^T_{ik}\land\mathrm{valid}(\hat y^I_{ik},\hat y^T_{ik})].
\]

主指标按五维等权宏平均，另报按全部判断对加权的 `micro_ticr`，两者不可互换。各维度分母 72/42/63/55/56 不同，原存在性任务的 189/315 整数门槛不再适用。A/B 分别按各自五维宏平均 TICR >=60% 判定；两路整体五维宏平均 balanced accuracy 均须 >50%，作为最低防退化条件。

同时报告逐维和整体两路准确率、balanced accuracy、阳性 F1、有效输出率、常量输出标记、共同正确率及共同错误对数。训练集众数对照必须报告。TICR 包含共同错误，100% 一致性不能单独证明判断有效，最低质量控制也不构成高准确率承诺。

评分核对全部预期 ID、双模态配对、问题哈希、固定 caption 索引、模型与解码来源、完整数据哈希、原 A/B 筛选后的 ID 和类别数。缺失、重复、错误协议、混合权重或 smoke 输出拒绝评分。完整基准标记需要转换审计支持，部分数据不能获得通过标记。

报告包含按场景 bootstrap 的 TICR 95% 区间（seed 42，2000 次），同场景的多个维度共同抽样，并在每次抽样中重新计算各任务分母；不把 288 个相关判断对当成 288 个独立场景。

本文件第 4 节记录历史原 LLaVA 视觉塔的极性训练。真实原始 MoralCLIP 视觉塔接入基线的结构、训练及实测结果见 [MORALCLIP_LLAVA_BASELINE.md](MORALCLIP_LLAVA_BASELINE.md)。

## 4. 冻结训练与完整流程

LLaVA-1.5-7B 固定 revision `b234b804b114d9e37bb655e11cbbb5f5e971b7a9`。从原 `models/image-lora` 初始化（SHA-256 `8c7adaa741656e41f34434c347624844dcaa5a61589c6c0fef5274cc005eeb02`），不继续存在性任务 adapter。原视觉塔、投影器、基座语言参数与生成头冻结，只训练语言 LoRA，不新增分类头。

配置：3 epochs、BF16、batch 4、验证 batch 4、梯度累积 2、LR 2e-5、warmup ratio 0.03、cosine schedule、seed 42、不启用梯度检查点；正式优化共 3678 步。仅监督答案与 EOS，问题、图像和 padding 不计入 loss。验证损失最小的 checkpoint 决定最终权重，测试结果不参与选模。推理自由贪心生成，最多 16 tokens，不强制合法答案或图文一致。

顺序：数据检查 → 专项测试 → 真实 GPU 两步 smoke → adapter 重载 → 训练集众数对照 → 原 LoRA 新提示完整基线 → 正式训练 → 验证选中 adapter 的完整测试 → 三组评分 → 独立重算与报告。配置、数据、源码及初始化哈希在基线前冻结。仅记录后续视觉适配资格，不自动实现或启动第二阶段。

```bash
# 从仓库根目录运行；先按统一环境装依赖、下载固定基模并 git lfs pull。
python 3.1/run_polarity.py prepare
screen -L -Logfile ticr-polarity.screen.log -dmS ticr-polarity \
  python -u 3.1/scripts/run_polarity_experiment.py \
  --output 3.1/results/runs/ticr-polarity-v1
```

已缓存基模可追加 `--local-files-only`。每阶段单独日志，`status.json` 每 15 秒更新心跳、PID 和训练优化步数；验证进度不覆盖训练步数。异常恢复仅在原 runner 和子进程均退出后，使用同一 output 加 `--resume`；冻结配置和已完成产物哈希必须一致，再续最近 Trainer checkpoint。SSH 断开不会终止 screen 内实验。
